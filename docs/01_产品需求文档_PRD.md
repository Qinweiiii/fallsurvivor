# 1. 项目定位

## 1.1 项目名称

**秋招 OS（Job Hunt OS）**

这是一个服务于个人秋招过程的轻量级求职管理平台。

它的核心目标不是做一个招聘网站，也不是做一个复杂的无人值守投递
Agent，而是：

> **帮助用户更快地发现适合自己的岗位、整理准备投递的岗位、辅助完成重复性的申请表填写，并清晰记录整个秋招投递进度。**

项目优先级是：

1.  真正好用
2.  信息清晰
3.  操作简单
4.  自动化有价值但不过度
5.  维护成本低

**不要为了体现技术含量而过度设计。**

------------------------------------------------------------------------

# 2. 用户画像

系统默认服务于一名正在参加 2027 届秋招的计算机相关硕士学生。

当前求职方向：

-   后端开发
-   AI 后端
-   AI 全栈
-   Agent

技术语言偏好：

-   Go：主要语言
-   Python：可接受

城市优先级：

1.  深圳
2.  东莞
3.  广州
4.  北京
5.  上海

公司偏好：

-   大厂优先
-   外企优先
-   不限制于大厂

系统应该允许用户在「求职画像」页面随时修改这些条件。

------------------------------------------------------------------------

# 3. 产品核心流程

整个系统围绕下面这条流程设计：

``` text
发现岗位
   ↓
查看 / 筛选岗位
   ↓
加入岗位车
   ↓
准备投递
   ↓
辅助填写申请信息
   ↓
用户人工审核
   ↓
用户自己完成最终提交
   ↓
记录为已投递
   ↓
跟踪笔试 / 面试 / Offer
```

其中最重要的概念是：

> **岗位总览里的岗位 ≠ 用户准备投递的岗位。**

只有用户主动勾选并点击「加入岗位车」的岗位，才进入正式投递管理流程。

------------------------------------------------------------------------

# 4. 页面结构

建议使用左侧 Sidebar + 顶部 Header + 主内容区域的后台管理型布局。

Sidebar：

-   Dashboard
-   岗位总览
-   岗位车
-   投递进度
-   求职画像
-   设置

不需要做过多层级。

------------------------------------------------------------------------

# 5. 页面一：Dashboard

Dashboard 是进入系统后的首页。

## 5.1 核心数据

展示：

-   已发现岗位数
-   岗位车数量
-   待投递数量
-   已投递数量
-   笔试数量
-   面试数量
-   Offer 数量

使用简洁的统计卡片。

## 5.2 最近动态

展示最近：

-   新发现的高匹配岗位
-   新加入岗位车的岗位
-   最近完成投递的岗位
-   即将截止的岗位

## 5.3 即将截止

如果岗位存在截止日期，显示：

-   公司
-   岗位
-   截止日期
-   剩余时间

没有截止日期时不要强行推测。

------------------------------------------------------------------------

# 6. 页面二：岗位总览

这是系统最重要的页面。

## 6.1 顶部区域

页面标题：

> 岗位总览

副标题可以显示：

> 根据你的求职画像，为你发现值得关注的岗位。

主要按钮：

> **获取岗位**

点击后触发一次岗位搜索任务。

**不要求实时自动刷新。**

用户点击「获取岗位」时才主动获取。

------------------------------------------------------------------------

# 7. 岗位获取逻辑

搜索来源优先级：

1.  公司官方招聘网站
2.  BOSS直聘
3.  Tavily 全网搜索

第一版不要求覆盖所有招聘网站。

每次获取岗位时：

``` text
读取求职画像
↓
生成若干搜索关键词
↓
调用岗位来源
↓
收集原始岗位
↓
标准化
↓
去重
↓
计算匹配度
↓
保存
↓
刷新岗位列表
```

用户不需要等待页面一直自动刷新。

可以显示：

> 正在获取岗位......

以及：

> 本次新增 27 个岗位，发现 43 个重复岗位。

------------------------------------------------------------------------

# 8. 岗位表格

表格只展示真正重要的信息。

推荐字段：

  选择   公司   部门 / 业务   岗位   地点   匹配度   状态   操作
  ------ ------ ------------- ------ ------ -------- ------ ------

不要在表格里直接展示完整 JD。

### 公司

例如：

> 腾讯

### 部门 / 业务

例如：

> AI Infra

如果无法识别部门，则显示：

> ------

### 岗位

例如：

> 后端开发工程师

### 地点

例如：

> 深圳

### 匹配度

显示：

> 94%

可以使用轻量级 Badge。

### 状态

例如：

-   未处理
-   已在岗位车
-   已准备投递
-   已投递
-   已结束

### 操作

只保留：

> 详细信息

------------------------------------------------------------------------

# 9. 岗位详情

点击「详细信息」后打开右侧 Drawer。

不要跳转到新页面。

Drawer 展示：

## 基础信息

-   公司
-   部门 / 业务
-   岗位
-   工作地点
-   招聘届次
-   岗位类型
-   来源
-   发布时间
-   截止时间（如果有）

## AI 匹配分析

展示：

-   匹配度
-   为什么匹配
-   用户优势
-   可能的短板

例如：

``` text
匹配度 93%

✓ Go 技术栈匹配
✓ 后端开发经历匹配
✓ LLM / Agent 项目匹配
✓ 深圳地点符合偏好

需要注意：
△ JD 提到 Kubernetes，但简历相关经历较少
```

## JD

完整展示：

-   岗位描述
-   岗位职责
-   任职要求
-   技术要求

保留原始 JD 文本，不要只展示 LLM 总结。

## 操作

底部固定：

-   加入岗位车
-   查看原网页

------------------------------------------------------------------------

# 10. 岗位筛选

必须支持经典后台筛选。

至少支持：

### 公司

文本搜索 / 多选。

### 岗位

支持关键词：

-   后端
-   AI 后端
-   Agent
-   AI 全栈
-   Infra

### 城市

多选。

### 匹配度

例如：

-   全部
-   80+
-   90+
-   95+

### 状态

例如：

-   未处理
-   岗位车
-   已投递

### 技术语言

例如：

-   Go
-   Python
-   Java
-   C++

筛选应该支持组合。

------------------------------------------------------------------------

# 11. 分页

岗位数量可能较多，因此必须分页。

默认：

> 每页 20 条

可选：

-   20
-   50
-   100

分页由后端数据库查询实现，不要前端一次加载全部数据再分页。

------------------------------------------------------------------------

# 12. 岗位车

岗位车是一个明确的用户意图状态。

定义：

> 加入岗位车 = 用户明确表示"这个岗位我准备投"。

页面展示：

-   公司
-   部门 / 业务
-   岗位
-   地点
-   匹配度
-   加入时间
-   投递状态

支持：

-   勾选
-   批量移出岗位车
-   批量开始准备投递
-   单个打开详情

------------------------------------------------------------------------

# 13. 投递管理

投递管理页面展示已经准备投递的岗位。

状态：

-   待准备
-   填写中
-   等待人工操作
-   待最终审核
-   已完成投递

用户可以批量选择任务。

------------------------------------------------------------------------

# 14. 辅助填写

系统可以辅助填写招聘网站申请表。

允许自动填写：

-   姓名
-   手机号
-   邮箱
-   学校
-   专业
-   学历
-   毕业年份
-   技术栈
-   项目经历
-   实习经历
-   常规求职信息

敏感信息必须留空：

-   身份证号
-   护照号
-   银行卡
-   密码
-   短信验证码
-   邮箱验证码
-   MFA
-   人脸识别相关内容

这些内容由用户自己完成。

------------------------------------------------------------------------

# 15. 最终提交

系统必须停在最终提交前。

流程：

``` text
AI 辅助填写
↓
用户接管
↓
用户检查
↓
用户自己点击招聘网站最终提交按钮
↓
回到系统
↓
点击“已完成投递”
```

系统不得自动点击最终提交按钮。

------------------------------------------------------------------------

# 16. 投递进度

投递完成后进入投递进度页面。

支持状态：

-   已投递
-   笔试
-   一面
-   二面
-   HR 面
-   Offer
-   拒绝
-   主动撤回

未完成任务显示在上方。

已完成 / 结束任务：

-   灰化
-   移动到列表底部
-   默认可以折叠

------------------------------------------------------------------------

用户可以修改：

## 求职方向

-   后端
-   AI 后端
-   AI 全栈
-   Agent

## 技术语言

-   Go
-   Python
-   Java
-   C++
-   其他

支持设置优先级。

## 城市

支持排序：


-   大厂

# 18. 视觉设计要求

前端视觉参考用户提供的参考图。

参考方向：

-   轻盈
-   可爱
-   柔和
-   明亮
-   有轻微梦幻感
-   白色 / 淡紫 / 淡粉 / 淡蓝等低饱和色
-   圆角卡片
-   柔和阴影
-   少量装饰元素
-   清晰的后台管理结构

但是：

> **只参考视觉语言，不照搬参考图的信息布局。**

本项目是求职管理系统，所以信息密度、表格、筛选器、Drawer、状态 Badge
等必须以求职管理场景为第一优先级。

不要为了追求"可爱"而牺牲信息可读性。

不要直接复制 Hello Kitty、Disney 等受版权保护的具体角色素材。

可以使用原创：

-   星星
-   小云朵
-   爱心
-   文件夹
-   小花
-   小魔法棒
-   简洁的原创吉祥物

------------------------------------------------------------------------

# 19. 交互风格

整体感觉：

> "一个很好用、很舒服的个人秋招工作台。"

而不是：

> "一个严肃的企业 HR 系统。"

按钮、Badge、Card 可以稍微可爱。

但是：

-   表格
-   JD
-   筛选器
-   状态
-   操作按钮

必须清晰、规整、易读。

# 21. 不要做过度复杂的功能

第一版明确不需要：

-   微服务
-   Kubernetes
-   复杂 Agent 编排平台
-   多租户
-   权限中心
-   企业级 RBAC
-   复杂消息治理
-   复杂推荐系统
-   自动无人值守投递

这是一个个人使用工具。

**优先保证稳定、简单、好用。**
