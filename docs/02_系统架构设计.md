# 1. 架构目标

本项目是个人使用的秋招管理工具。

架构设计遵循：

> **单体优先、模块清晰、异步任务适度使用、AI
> 能力独立封装、浏览器自动化独立。**

不要为了技术复杂度而拆成大量微服务。

# 4. Backend 模块

建议 Go Backend 按业务模块组织：

``` text
backend/
├── cmd/
│   └── server/
├── internal/
│   ├── handler/
│   ├── service/
│   │   ├── job/
│   │   ├── search/
│   │   ├── application/
│   │   ├── resume/
│   │   └── profile/
│   ├── repository/
│   ├── model/
│   ├── ai/
│   ├── search/
│   ├── browser/
│   └── task/
├── pkg/
├── config/
└── migrations/
```

不要求严格按照这个目录。

核心原则：

> Handler 不直接操作数据库。

应该：

``` text
Handler
  ↓
Service
  ↓
Repository
  ↓
Database
```

------------------------------------------------------------------------

# 5. AI 模块

AI 模块只负责 AI 相关任务。

例如：

``` text
internal/ai/
├── deepseek.go
├── job_parser.go
├── job_matcher.go
├── query_generator.go
└── field_mapper.go
```

不要把 DeepSeek API 调用散落在业务代码里。

------------------------------------------------------------------------

# 6. Search 模块

统一抽象岗位来源：

``` go
type JobSource interface {
    Search(ctx context.Context, query SearchQuery) ([]RawJob, error)
}
```

实现：

``` text
OfficialSource
BossSource
TavilySource
```

以后增加新的来源不应该修改 Job Service。

# 8. 为什么不让 LLM 做全部事情

确定性问题由代码处理：

-   URL 去重
-   字段标准化
-   分页
-   排序
-   数据库筛选
-   状态机
-   时间计算

语义问题交给 DeepSeek：

-   JD 结构化
-   岗位方向识别
-   岗位匹配
-   搜索词生成
-   表单字段语义映射

这样系统更加稳定。

# 10. Browser Automation

Playwright 独立运行。

第一版建议：

``` text
Go Backend
    ↓
创建 Browser Task
    ↓
Playwright Worker
    ↓
打开本地浏览器
    ↓
执行页面读取 / 填写
    ↓
等待人工
```

不要让 Go 进程直接承担大量浏览器生命周期管理。

------------------------------------------------------------------------

# 11. 登录态

第一次登录：

``` text
打开招聘网站
↓
用户手动登录
↓
用户完成验证码 / MFA
↓
保存登录态
```

之后复用。

登录态只保存到本地安全目录。

禁止提交 Git。

------------------------------------------------------------------------

# 12. 人机协同

Browser Worker 可以：

-   打开页面
-   查找职位
-   读取表单
-   填写普通字段

遇到：

-   验证码
-   MFA
-   敏感字段
-   最终提交

必须暂停。

用户处理完成后点击继续。

# 14. 第一版部署

本地开发：

``` text
docker compose up
```

启动：

-   PostgreSQL
-   Redis
-   Backend
-   Frontend

Playwright 可以先运行在宿主机或单独容器。

不要求第一版部署到云服务器。

------------------------------------------------------------------------

# 15. 工程原则

1.  单体优先。
2.  模块边界清晰。
3.  AI 调用统一封装。
4.  外部 API 必须有 timeout。
5.  外部 API 失败必须可重试。
6.  搜索任务必须有状态。
7.  Browser Task 必须可暂停。
8.  用户最终提交必须人工完成。
9.  敏感信息不进入 LLM。
10. 不为了展示技术含量而增加基础设施。
